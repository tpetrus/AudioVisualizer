# Hub follow-ups: ledger

One row for every `FU-` follow-up id of the hub-regressions plan. This ledger replaces the open list that
`docs/agents/hub-scorecard.md` carried under "Follow-ups outside the fast lane"; that section is now a pointer here.
The slices are those of the `hub-followups` plan (`hub-followups.plan.md` and `contracts.md` in this folder).

Outcome vocabulary:

- **open**: not done yet; the Slice column names the slice that will close it.
- **fixed**: the behavior or tooling was changed; the last column names the commit.
- **documented**: kept as intended behavior and written down; the last column names the commit.
- **done earlier**: finished before this plan began; the last column names the commit or the line that records it.
- **deferred**: measured and left open past this plan with its evidence; the last column says what the next step needs.
- **won't-do (pending Trevor sign-off)**: proposed for closing with a reason. It is not closed until Trevor signs off
  and the sign-off is written into the row by whoever records it.

Each slice that closes an id updates its row in the same pull request.

## S5: bass-ink energy

Decision rule (plan AC6): keep the hub input only if, on every track, the set director starts as many transitions as
with the analyser input and each one within one beat (60 / the `.bpm` sidecar) of it. Measured with
`measureSetDirector` (`scripts/scorecard/engine/setDirector.ts`), whose `energy` option now has both inputs. The
analyser times match S4's exactly. Every track not listed started no transition on either input.

| Track             | BPM   | Analyser (before), s | Hub low end, thresholds unchanged, s | Within the rule |
| ----------------- | ----- | -------------------- | ------------------------------------ | --------------- |
| `6-8-time`        | 62    | 17.533               | 17.500                               | yes             |
| `beatless`        | 71    | none                 | 10.850, 23.417                       | no (count)      |
| `lonley`          | 140   | 10.783               | 7.367, 15.950                        | no (count)      |
| `summer2000`      | 127.5 | 23.567               | 23.333                               | yes             |
| `syncopationbass` | 98    | 21.733, 31.200       | 20.850, 31.000                       | no (0.88 s)     |

Retune: every ratio threshold of the director (`buildEnterRatio`, `dipRatio`, `softDipRatio`, `surgeRatio`,
`dropRatio`) raised to a power k, which moves it away from 1 as the hub's wider dynamics need. With k = 0.75 and 1.25
the same three fail. With k = 1.5 and 2, `lonley` passes (10.37 s) but `beatless` (11.05, 23.43 s) and `syncopationbass`
(20.88 s first) fail. With k = 2.5 and 3, `beatless` passes but `lonley` loses its transition and `syncopationbass` still
starts at 20.90 to 20.92 s. No k passes all tracks, and `syncopationbass` fails at every k, so the scene keeps the
analyser input (`DEFAULT_ENERGY_SOURCE = 'analyser'`) and no threshold changed. The hub path stays in the measure so the
comparison can be repeated. No live confirmation is needed in S7, since bass-ink's energy did not change.
