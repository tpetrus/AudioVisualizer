## Request

> Clean up all the UI elements and make them look nicer. Context: We have continued to build up the UI for this application, adding plenty of buttons and modals, but we never stepped back to create a proper design system. ## Problem

The UI grew ad hoc: three styling approaches (Tailwind utilities, buttonStyles.ts constants, ControlPanel.module.css with hex colors), no color or radius tokens in app.css, a gradient on landing cards, buttons and labels without a pointer cursor (Tailwind 4 preflight sets none), a level meter that steps at 10 Hz, and an enhanced graphics toggle (on origin/main) whose on/off state, recommendation and placement are unclear.

**Users:** Viewers who pick an audio source on the landing page and tune a visualizer in its settings panel; Contributors adding new controls or dialogs, who need one obvious set of styles to reuse

**Evidence:**
- app/app.css @theme only sets --font-sans
- ControlPanel.module.css uses #333/#555 buttons, a second button look next to buttonStyles.ts blue-600
- VisualizationCard.tsx:40 bg-gradient-to-t
- useLevelMeter.ts setInterval 100 ms with no CSS transition on the bar in ActiveSourcePanel.tsx
- Tailwind 4 preflight has no cursor pointer for button; dialog buttons, switch label and select lack it

## Goals

- One token-based design system in app/app.css @theme (dark gray surfaces, one blue accent, flat, no gradients, one radius and focus ring) plus shared primitives (Button, Switch, Dialog, Panel/Section, Field, Select, Range) that every screen uses
- Every interactable element shows the correct cursor (pointer; not-allowed when disabled; default for plain text)
- The audio level meter animates smoothly with no visible stepping
- Enhanced graphics shows its on/off state unmistakably, is marked Recommended, is offered once by a first-visit landing modal, and sits in a consistent place on the landing page and in the settings panel

## Non-goals

- No functional change: no new settings, no change to audio, rhythm, scene behavior or stored values other than the one new dismissal flag
- No external UI library or new runtime dependency
- No change to three.js scenes, shaders or the enhanced graphics render paths
- No light theme or theme switcher
- Enhanced graphics UX changes are proposals: the implementer presents them to the user before building them

## Decision

**O4**: O1's cheap base (app.css tokens and one base-layer cursor and focus rule, CSS-transition meter) plus O2's full primitive set, guarded storage and lint enforcement, plus O3's single EnhancedGraphicsControl in a Graphics section placed first in both the landing page and the settings panel, with a once-only modal. Sources: O1, O2, O3.

O4 keeps O1's cheap, convention-fitting base (tokens in app.css, a base-layer cursor rule, a transition-only meter) but adds what O1 lacks for the verification bar: a full primitive set enforced by lint, so the system is reused automatically, and O3's single Graphics section so enhanced graphics is clear and identically placed. It costs more effort than O1, which weighs least here (D9).

**Approach:**
- S0 on a branch from origin/main records the real enhanced graphics store, hook and UI paths
- Tokens and base layer in app/app.css (from O1 and O3)
- Primitives in app/components/ui: Button, Switch, Dialog, Section, Field, Select, Range, Badge, each with a spec (from O2)
- Migrate every screen, delete buttonStyles.ts and hex colors in ControlPanel.module.css, flat caption band on cards; ESLint no-restricted-syntax for raw button/select/range JSX and color literals outside ui and app.css (from O2)
- Meter: transform scaleX plus a 100 ms linear transition on the existing 10 Hz state (from O1 and O3)
- EnhancedGraphicsControl and EnhancedGraphicsPrompt, gated on user confirmation of the concrete design (from O3, D6)

## Design

A token layer in app/app.css @theme (surface-0/1/2 dark grays, border, text, text-muted, one blue accent and accent-hover, danger, one radius, a focus ring) plus a base layer that gives every native interactive element the right cursor and focus-visible ring. A small primitives library in app/components/ui renders every button, switch, dialog, section, field, select, range and badge from those tokens. All screens migrate onto it; buttonStyles.ts goes and ControlPanel.module.css keeps only layout that needs real CSS, in tokens. A lint rule keeps raw controls and color literals out of feature code. The meter animates with a transition. Enhanced graphics gets one control, placed first in a Graphics section in both places, and a once-only landing modal, built only after the user approves the concrete design.
